# Project notes

Static, single-page dashboard. No framework, no bundler. D3 v7.8.5 is loaded from cdnjs. Forked from the Well & Call cocktail dashboard (`../back-bar-dashboard`): same code, with drinks → menu items, restaurants → menu lines, restaurant groups → brands, zero-proof → add-ons (sides, drinks, desserts).

- Edit `src/template.html`, then run `python3 scripts/build.py` to regenerate `index.html`. Never edit `index.html` by hand.
- Data changes: edit `data/items_raw.tsv` (columns: group, line, section, item, price, cal, ingredients) or `data/station.tsv` (the build-your-own line with up-charges and nutrition), then run `python3 scripts/normalize.py data/items_raw.tsv data/items.json` before building. Add a rule to `RULES` in normalize.py for any new ingredient wording; order matters ("harissa honey chicken" before "harissa", "pita crisps" before "pita", "red pepper hummus" before "hummus"). The script fails loudly on unmapped ingredients, including station components. `data/sources.md` records URLs, read dates and judgment calls; keep it current.
- Vocabulary in the JSON and code: `group` = brand (CAVA, Sweetgreen, Chipotle), `line` = menu line (names must be unique across brands, since the code keys on them: CAVA has Bowls, Chipotle has Burrito bowls), `item`, `small` = add-on (a line whose name matches side/drink/dessert/sweet/chips/bottled/fountain, see `SMALL_LINE` in normalize.py), `veg` = no meat or fish, `cal` = menu calories. In the template the line list is `LINES`, `LINE_GROUP`, `selLines()`, `state.lines`; `HOME` is the first brand. The sidebar filters by brand or line and starts with CAVA only; Compare brands and Head to head use every brand. `state.small` toggles add-ons.
- `STATION` (from `data/station.json`) is CAVA's build-your-own catalog (competitors have none): station, component, `canon` (the canonical component name, so it joins to item ingredients), `upcharge`, nutrition. `stationUnused()` lists components no curated CAVA item uses (Prep tile, Menu gaps). `BYO_BASE` is the build-your-own price at the Dupont store.
- Each item has `ings` (deduped canonical components with `cat`) and `parts` (every menu ingredient line as `[raw, canonical]`, used for display).
- Categories (`cat`) roll up to 9 families via `CAT2FAM`: green, grain, dip, main, topping, dressing, bread, sweet, drink. Family colors are the `--f-*` CSS tokens. Mains split into Chicken / Beef, pork & lamb / Seafood / Plant-based mains; named preparations stay brand-specific (Grilled chicken, Blackened chicken, Adobo chicken) while generic produce merges across brands; `MAIN_STYLE` and `styleOf()` give the "main" of an item for the cost/sales simulation and Head to head.
- Light theme only, by design. Brand: "Spread Sheet" (dips and spreads + spreadsheet), saffron `--accent`, olive `--teal` (token name kept from the fork), fonts Geist + Geist Mono. Price axes share `PMAX` / `PTICKS` ($0–20).
- Main JS entry points: `render()` re-renders everything on filter change; `setView(name)` switches views (`overview`, `components`, `matrix`, `map`, `prep`, `price`, `gaps`, `groups`, `h2h`, `costs`, `about`). `renderChord`, `renderOps`, `renderOverview`, `renderGroups`, `renderH2H` and `renderCosts` each own one view. `h2h` compares two entities (`r:<line>` or `g:<brand>` ids, stored in `h2h` / localStorage `cv-h2h`) and defaults to Bowls vs Pitas. The Compare brands nav button hides itself if only one brand is loaded.
- `og.png` (link preview, 1200x630) is rendered by `scripts/make_og.py` from `src/og-card.html` plus a headless screenshot of the built page opened on Head to head (CAVA vs Sweetgreen). Re-run it after visible Overview or data changes. og:image URLs point at https://shualuke.github.io/cava-dashboard/.
- Template content above `<!--BODY-->` is emitted into `<head>` by build.py.
- Tooltips: give any element `data-tip="<html>"` (use `tipAttr()`, `ttRows()`, `ttList()`). One delegated handler does hover on desktop, tap-to-show / tap-again-to-open on touch, and focus for keyboard.
- The `costs` view uses made-up, adjustable per-component-type costs (`COST_DEFAULT`, target food cost 30%) and a seeded random sales simulation (`simulate()`, `sim.seed`). Keep both labeled as assumed/simulated, never as CAVA's real costs or sales.
- Detail views share one renderer, `renderInspect(box, ds, S, target, nav, opts)`, used by the pairing map panel, the matrix panel (`renderPair`) and the overview drawer (`openDrawer`). Sub-map helpers: `subMap()`, `fanMap()`, `subChord()`, wired by `wireSubMap()`.
- Guided tour: `TOUR` steps with `tourStart()`; auto-starts once per browser (`cv-tour-done`), replay via the sidebar. `window.__notour` suppresses it. Update the steps when views change.
- Overview must fit one desktop screen (no page scroll) at 1280×720 and up; check this after layout changes.
- Prices are one downtown DC store's per chain (CAVA Dupont Circle, Sweetgreen Farragut Square, Chipotle Dupont Circle) and vary by location; say so wherever prices are shown. Sweetgreen's bottled drinks and sweets have no store price (blank).
- Good next steps: a monthly re-read of the three menus to track changes; allergen flags from CAVA's nutrition PDF; station catalogs for Sweetgreen and Chipotle so their build-your-own lines compare too.
